# 3. Чек-лист для Code Review

Слияние ветки в `develop` допускается только при наличии минимум двух подтверждений (Approve) от разработчиков и финального согласования от Tech Lead. Проверка кода выполняется по следующим критериям, специфичным для доменов кампуса:

| Область проверки | Контрольные вопросы и требования для АИС «Умный кампус» |
| :--- | :--- |
| **Логика расписания и аудиторного фонда** | Учтены ли временные зоны, четность/нечетность учебных недель и праздничные дни? Исключена ли возможность двойного бронирования одной аудитории на одно время (проверка коллизий)? |
| **Работа со СКУД и мобильными пропусками** | Ограничено ли время жизни токена динамического QR-кода (TTL не более 30–60 секунд) для защиты от пересылки скриншотов? Корректно ли обрабатывается отзыв пропуска при отчислении студента или увольнении сотрудника? |
| **Интеграция с аппаратным обеспечением** | Предусмотрена ли локальная кэш-очередь событий прохода на случай потери сетевого соединения между сервером АИС и контроллерами турникетов в корпусах? |
| **Защита персональных данных (152-ФЗ)** | Маскируются ли персональные данные студентов (ФИО, номер студбилета, фото) в системных логах? Используется ли шифрование при передаче данных между мобильным клиентом и API шлюзом? |
| **Производительность в пиковые часы** | Оптимизированы ли запросы к БД с учетом пиковых нагрузок (массовый проход студентов через турникеты в 8:30 утра и массовый просмотр расписания на переменах)? Используется ли кэширование (Redis) для статичного расписания? |
| **Тестовое покрытие сценариев** | Написаны ли юнит-тесты на граничные случаи: попытка прохода по просроченному QR-коду, попытка входа в закрытую лабораторию без спецдопуска, перенос пары в другую аудиторию? |
