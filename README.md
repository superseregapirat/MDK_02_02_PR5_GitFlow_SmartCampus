# АИС «Умный кампус» — Регламент Git Flow (МДК 02.02)

Репозиторий содержит организационную структуру и правила командной разработки информационной системы **«Умный кампус»** (Вариант №1). Проект охватывает модули управления расписанием занятий, интеграции со СКУД турникетов и выпуска мобильных QR/NFC-пропусков.

## Состав проекта

* `src/SmartCampus.Core/` — ядро системы, доменные модели студентов, аудиторий и пропусков.
* `src/SmartCampus.Infrastructure/` — модули интеграции с оборудованием СКУД и база данных.
* `src/SmartCampus.Api/` — серверный программный интерфейс для мобильного и веб-клиентов.
* `tests/SmartCampus.UnitTests/` — автоматизированные модульные тесты бизнес-логики.
* `CONTRIBUTING.md` — инструкция по работе с ветками и критерии проверки кода (Code Review).

## Стратегия ветвления

В разработке используется модель **Git Flow**, разделяющая стабильный контур вуза и текущую разработку:

| Ветка | Назначение | Правила работы |
| :--- | :--- | :--- |
| `main` | Промышленная эксплуатация на серверах университета | Прямые изменения запрещены, слияние только из `release/*` или `hotfix/*` |
| `develop` | Основная ветка для сборки и интеграции готовых задач | Принимает изменения из `feature/*` после прохождения CI и Code Review |
| `feature/*` | Разработка отдельного функционала (пример: `feature/CAMPUS-408-guest-pass`) | Создается от `develop`, после утверждения вливается через Squash and Merge |
| `release/*` | Подготовка и тестирование новой версии перед началом учебного модуля | Исправление мелких дефектов, финальная проверка QA-инженером |
| `hotfix/*` | Срочное устранение критических сбоев на проходной или в расписании | Создается от `main`, после исправления вливается в `main` и `develop` |

## Распределение ролей

* **Tech Lead (Тимлид):** отвечает за архитектуру .NET-решения, настраивает защиту веток `main` и `develop`, проводит финальный аудит кода и формирует релизы.
* **Backend Developer (.NET/C#):** разрабатывает логику проверки коллизий расписания, сервисы генерации токенов доступа и шлюзы обмена со СКУД.
* **Mobile / Frontend Developer:** реализует интерфейс личного кабинета и клиентский модуль отображения динамического QR-пропуска.
* **QA Engineer:** проверяет корректность работы системы на тестовом стенде перед выпуском релиза.
